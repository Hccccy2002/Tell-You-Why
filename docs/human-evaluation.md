# 人工评测基准

入口：右上角 **⋯ → 开发者工具 → 质量评测 → 管理人工评测题库**。

这项功能把两种工作分开：先核对题目、参考答案和证据，形成可复用的标注基准；再对某轮模型的实际输出做人工评价。确认参考答案不会自动给模型答案打分，执行成功、引用定位有效也不等于回答正确。

## 1. 选择资料、建立题目

在“选择已导入 PDF”中选择 PDF，再点“切换标注资料”。资料需要已发布索引，部分内容可检索的资料也可以选择，但需要核对 OCR 和缺失内容。每份 PDF 的每个已发布版本分别保留草稿，切换后可以恢复；封存版本不随草稿编辑改变。

首次打开提供原来的 40 道教材题，全部标记为未人工确认、历史回归题。同一本 PDF 的索引编号变化时，只有原 PDF 指纹、原文块和引用均通过校验，才复用这些候选题；原文不能对应时建立空题库，不自动迁移错误标签。其他 PDF 从新增题目开始。

建议逐步积累 50–100 题，当前每份草稿上限 500 题；这个数量是建设建议，不是已经完成人工标注的数量。可以先用少量题目验证流程，报告会显示实际样本数。

每道题填写：

- 问题、题型：直接查询、跨段信息、概念辨析、资料没有答案、图表信息不足、OCR 错误、错误前提。
- 分组：开发集、回归集、留出测试集。
- 预期行为：依据原文回答、说明证据不足并拒答、纠正错误前提后回答。
- 参考答案、可接受回答与判定标准。注明关键事实、允许的不同表述、不可遗漏的部分及拒答依据。
- 参考证据：输入 PDF 物理页码，读取本页文字，加入原文块；可同时查看 PDF 原页核对 OCR。可回答题至少一条证据，多段题至少两条。没有答案的题目不能仅因检索为空就确定，应人工核对资料范围并说明原因。

未入索引的原文仍可作为参考证据，不能为了提高检索得分将这类失败样本删除。OCR 错误题应核对 PDF 图像，参考答案描述正确内容，保留索引文本的实际状况。

填写标注复核人和核对依据，再勾选人工确认后保存。确认默认不勾选，修改内容后需要重新确认。只保存草稿不会进入人工基准。署名是本机声明，不是身份认证；系统无法代替人的事实核验。

## 2. 封存与留出集

“封存已确认题目”只收录人工确认的题目，并重新校验 PDF、知识库文件、证据页码、引用及原文哈希。生成独立版本和 SHA-256 指纹，后续修改需要重新封存。

历史 40 题已参与过实验，不能改名后充当留出题。新增留出题应由评审者独立编写，避免开发题的近似改写，也不要用于挑选提示词、召回参数或模型。

运行留出分组需要明确声明方案已固定。系统在执行前记录题目使用，即使本轮中断，也保守地算作已暴露；同一问题在不同封存版本中的重复使用会被标记。首次使用仅表示本机没有使用记录，不证明题目未在其他设备使用，也无法检测语义相近的改写。看过结果后再调参，这批题应按回归题解释，重新构建留出集。

## 3. 运行评测

选择“RAG Top 5”或“真实模型”，勾选“本轮使用人工标注基准”，选择封存版本和分组。分组默认回归，留出不会混入默认运行。

- RAG Top 5：对比展示原文的原检索与重排结果，保持相同五条原文预算；不调用在线模型。
- 真实模型：每轮明确选择 1–8 个题号，最多 40 次模型请求。题号留空表示本组全部，超过 8 道会拒绝启动，不会静默截取。可分多轮覆盖较大题库。
- 人工基准的真实模型套件只评测问答；Agent 流程套件继续独立报告。内置历史套件保留原有行为。

每个任务保存封存题库和本轮选择快照，生成器只收到问题和检索证据，不接收参考答案、标签或判定标准。参考标签供评分和人工复核使用。

真实模型评测会把所选资料摘录发送给用户选择的模型服务，点击开始才执行；题库编辑、封存、查看及复核不调用在线模型。

## 4. 评价模型输出

展开已结束的真实模型报告，对照输出、参考答案、参考证据和实际召回材料，填写四项判断：

| 判断             | 通过条件                                         |
| ---------------- | ------------------------------------------------ |
| 事实正确性       | 关键陈述没有事实错误或矛盾                       |
| 回答完整性       | 覆盖问题要求的关键部分                           |
| 证据支持情况     | 原文支持关键结论，或准确说明证据限制             |
| 回答行为是否恰当 | 该回答时回答、该拒答时说明不足、错误前提得到纠正 |

四项都填写并提供备注，才计入新基准的人工分数；任意一项为否，本题标记未通过。旧报告继续使用原有三项要求，不补造行为评分。失败或未执行的生成不能获得内容质量分数。

报告分别显示：执行完成情况、检索指标、人工复核进度、事实正确率、完整率、证据支持率、应拒答题通过率，以及按题型和分组统计的全部判断通过率。应拒答题通过率的分母是已复核且预期拒答的题目，不是所有问题；无适用样本显示待复核。分类卡片同时显示通过数、已复核数和可复核总数。未复核、草稿和未执行题目不会当作正确或错误，需结合执行与复核覆盖率解释结果。

人工与 AI 评价分开保存、分开统计。脚本 Agent 流程成功率不代表真实回答质量或学习效果。

## 5. 导出与复现

“导出此封存题库”导出完整不可变标签；“导出 JSON 报告”导出该轮指标、执行数据、所用分组、参考标注和最新人工评价。报告包含题库指纹，旧评审不能套用到修改后的输出。

数据保存在应用数据目录 `evaluations/` 下：

- `benchmark/draft.json`：当前资料的标注草稿。
- `benchmark/drafts/`：其他资料/版本的草稿。
- `benchmark/releases/<指纹>/dataset.json`：不可变基准。
- `benchmark/uses.json`：题目使用记录。
- `<任务 ID>/dataset.json`、`selection.json`：本轮快照与题目选择。
- `<任务 ID>/human-review.json`：实际模型输出的人工评审。

桌面应用串行保存题库请求，修改带版本号以拒绝旧页面覆盖；不支持同时用外部编辑器修改这些文件。删除使用记录会丢失本机暴露历史，不能据此宣称题目重新变为独立测试集。

开发验证命令：

```powershell
.\rag-service\.venv\Scripts\python.exe -m unittest discover -s evals/textbook
.\rag-service\.venv\Scripts\python.exe -m unittest discover -s evals -p test_panel.py
npm test
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline
```

本地联调测试 `desktop_benchmark_snapshot_smoke` 需要已发布的 PDF、Python 和本地检索模型，运行于独立临时目录。它使用明确标记的自动化测试署名和模拟答案，检查题库、真实本地检索、评分和保存流程，**不构成人工质量证据，也不调用在线模型**。

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline desktop_benchmark_snapshot_smoke -- --ignored --nocapture
```
