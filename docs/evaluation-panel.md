# APP 质量评测面板

入口：右上角 **⋯ → 质量评测**。选择评测类型后点击开始；打开面板、浏览报告和切换通道都不会自动启动评测。

| 类型       | 运行内容                                                           | 运行条件                                         |
| ---------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| Agent 流程 | 10 个受控场景，经真实 Agent 循环、工具分发与独立 SQLite 数据库执行 | 项目 Python 环境；无需 API Key                   |
| RAG Top 5  | 40 道固定教材题，对比原检索前 5 条与本地重排后的前 5 条            | 已索引的《计算机组成原理》、原模型与本地重排模型 |
| 真实模型   | 8 道教材问答与一次真实教材复习 Agent；共享每轮 40 次请求上限       | 当前已配置、通过连接测试的模型通道               |

面板直接调用桌面运行器，不依赖安装 Rust/Cargo。Python 环境沿用 PDF 组件的 `TELLWHY_RAG_SERVICE`、`TELLWHY_PYTHON` 和 `TELLWHY_KB_DATA` 配置；评测脚本位于项目 `evals/` 目录。教材和模型文件会按现有评测协议校验，无法满足时显示失败原因，不替换成模拟成功结果。

## 进度、停止与历史

同一 APP 进程同时运行一项评测。运行中可切换页面，返回后恢复进度。停止本地检索会结束评测子进程；停止真实模型评测后，已经发出的请求可能仍返回并计费，后续请求不会继续发送。

任务及报告存储在应用数据目录的 `evaluations/<任务 ID>/`，历史选择器展示最近 50 次任务。各任务使用自己的目录和复习数据库，真实用户的学习记录不会参与模拟答题或被评测改写。重启后未结束的任务标记为中断，不自动重发 API 请求。重新开始会生成新任务。

Agent 与真实模型运行逐步保存结果；未执行的题目保持未完成。RAG Top 5 需要完成整轮后才能生成评分报告。任务完成表示评测执行结束，逐项“未通过”仍会保留，不能将执行完成解读为所有检查通过。

## 报告

报告显示指标、数据集版本及逐项结果，可筛选未通过或待评估条目。展开条目可查看检查项、模型回答、参考答案、相关原文和 Agent 执行追踪；RAG 同时保留重排前后的原文。原始执行数据可展开查看。

“导出 JSON 报告”使用系统保存对话框，导出任务、指标、逐项数据和复核模板；取消对话框不会提示导出成功。报告中的真实模型用量只统计供应商实际返回值，缺失用量显示未知。报告不包含 API Key、系统提示词、原始供应商响应或模型隐藏推理。

流程分数、引用定位与回答正确性分别报告。真实模型输出初始状态为待复核，不自动推算正确率。参考答案沿用现有数据集的 AI 核验标注，尚未经过人工复核。

## 人工复核

在“评测记录”中选择一轮已结束的**真实模型评测**，展开问答，查看模型回答、引用摘录、参考答案与相关原文，然后填写“人工复核”。已有面板报告也可直接复核，无需重新调用模型。

- **事实正确性**：关键陈述有无事实错误或矛盾。
- **回答完整性**：是否覆盖问题的关键部分。
- **证据支持情况**：原文是否支持关键结论；证据不足时是否恰当说明限制。回答声称“证据不足”并不自动通过，需要结合问题和原文判断。
- **复核备注与复核人**：记录判断依据及署名；默认署名“本机用户”可修改，这不是身份认证。

三项判断均默认为“待判断”，没有预选的通过结论。可以先“保存草稿”，重启后继续填写。三项判断全部完成且备注非空时，“保存复核”会更新人工质量指标；任意一项不符合，题目显示未通过。清空一项判断或备注后保存，会重新变为草稿。没有生成回答的题目不提供复核表单。

人工复核进度的分母是已生成、可复核的问答数量；“生成完成”的分母仍是计划题目数量。三项质量分数只以已完成复核的题目为分母，同时显示样本数量。例如只复核 1/8 道题，即使该题通过，100% 和“符合 1 / 1 道”也只表示这一道题。草稿和未复核题目不计为错误或正确。真实模型报告里的 Agent 条目继续表示执行流程状态，不计入这三项问答质量分数；Agent 流程和 RAG Top 5 报告继续使用原有自动检查。

编辑过程中筛选、刷新或切换历史记录会保留当前面板内尚未保存的输入；离开评测面板或退出 APP 前请点击保存。保存失败会保留输入并显示原因。如果另一处已修改同一条复核，旧版本不能覆盖新版本；刷新后可以放弃本地修改、读取已保存版本，再重新填写。

复核独立写入任务目录的 `human-review.json`，包含报告指纹、数据集指纹、逐题结果指纹、复核人、三项判断、备注、修改时间和版本号。原始 `report.json`、模型输出及学习数据库保持原样。报告或原文发生变化后，旧标注停止计分，面板提示不匹配。每次保存替换该题当前复核，保留递增版本号；本阶段不提供历史修改审计或多轮实验对比。

导出的 JSON 包含最新人工指标和 `report.raw.human_review` 标注，可将该字段另存为 JSON 交给教材命令行评分器的 `--annotations` 参数。人工与 AI 复核分别统计；旧版 CLI 标注未填写完整性时，该指标保持未评估。

现有命令行评测仍可使用，运行方式见 [Agent 评测](../evals/review-agent/README.md) 和 [教材评测](../evals/textbook/README.md)。面板中的历史从面板新建任务开始记录；之前的命令行报告保留在原目录。

## 验证入口

```powershell
node node_modules/vitest/vitest.mjs run
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline desktop_evaluation_review_smoke -- --ignored --nocapture
.\rag-service\.venv\Scripts\python.exe -m unittest discover -s evals -p test_panel.py
```

`desktop_evaluation_model_smoke` 是显式启用的真实 API 联调入口，要求 `TELLWHY_PANEL_PROFILE_DB` 指定配置数据库副本、`TELLWHY_PANEL_OUTPUT` 指定独立输出目录，使用当前 Windows 用户凭据库中的 DeepSeek Key，最多 40 次请求。默认测试不会执行真实 API 调用。

2026-09-13 联调：10 个 Agent 受控场景全部通过；真实教材 Top 5 的 40 题完整跑通，34 道有标签题的命中率为 88.2%，MRR@5 为 0.814；真实模型 8 道问答和一次复习 Agent 执行完成，实际请求 20 次，供应商共报告 80,310 tokens。回答正确性仍为待复核。真实调用使用已授权配置，在正常 Windows 用户环境读取系统凭据，结果位于独立评测目录。

人工复核验证：前端 128 项、Rust 135 项、评测脚本 27 项和 RAG 服务 69 项测试通过；另用已保存的真实模型报告回放草稿保存、完成复核、重启恢复及导出，桌面人工评分与 Python 评分器一致。回放使用独立测试目录和明确标记的测试判断，不是真实人工评价，不会改写原报告或发送 API 请求。界面在 320×360、360×440、480×360、800×700 窗口检查通过。

本地回放入口为忽略测试 `desktop_human_review_replay`，要求 `TELLWHY_REVIEW_FIXTURE` 指定已有真实模型 `report.json`，`TELLWHY_REVIEW_OUTPUT` 指定独立测试输出目录。该入口仅用于开发验证。
