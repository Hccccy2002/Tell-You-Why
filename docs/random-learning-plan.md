实施结果及逐阶段测试见 [随机学习验收记录](random-learning-acceptance.md)，操作步骤见 [随机学习使用说明](random-learning-guide.md)。下文保留原始执行计划。

## 1. 阶段目标与范围

用户选择一本知识库及章节范围后，可以连续随机学习，看到问题、揭晓答案、查看教材出处，并标记“掌握”或“需复习”。应用重启后仍保留学习状态、近期记录和当前进度。

本阶段提供两条路径：

- **随机学已有卡片**：直接读取本地已存教材卡，支持离线使用，无须配置模型或启动检索进程。
- **随机生成新卡**：本地按章节和已有记录选择教材素材，展示原文摘录；用户点击发送后，复用现有 RAG 生成和审核流程，一次生成一张。

两条路径使用相同的学习状态和避重记录。已有卡不足时显示“随机生成新卡”入口，由用户主动发起生成。

本阶段先完成单库、整本或一个章节子树的学习。批量生成、自动间隔复习、知识点语义聚类、难度分级、跨书混合学习和新增追问能力另行安排；不将完整路线阶段 5 的所有功能都算作本次交付。

## 3. 用户操作与默认规则

入口放在“PDF 知识库 → 具体教材 → 随机学习”，沿用当前选中的章节范围。

1. 选择“随机学已有卡片”，默认优先未学习卡片。
2. 先展示问题，点击“揭晓答案”后显示答案、解释、引用和学习反馈。
3. 可选择“掌握”“需复习”“下一张”；“跳过”只记录本次展示和跳过，不代表已经学习。
4. 查看原文后返回同一卡片；上一张用于回看，不重新抽样。
5. 需要新内容时点击“随机生成新卡”，预览素材后主动发送；成功保存的卡片仍需揭晓或反馈才能改变学习状态。
6. 再次进入或重启应用时恢复当前卡片、揭晓状态、章节范围和本轮已展示集合。

默认排除已掌握卡片；“只看需复习”和“包含已掌握”是显式筛选项。学习状态按钮直接保存并允许撤销，不执行永久归档。

页面显示各状态的卡片数量、今日揭晓卡片数及章节素材覆盖数。“今日已学习”按本地日期内发生揭晓或明确学习反馈的不同卡片计数，跳过不计入；章节覆盖只按主素材统计，补充引用不代表已学完。指标名称明确为“卡片状态/素材覆盖”，不将它们解释为整本教材的真实掌握百分比。

## 4. 随机学习与近期避重策略

### 4.1 随机学已有卡片

按以下顺序筛选：

1. 限定知识库及章节子树，应用学习状态筛选。
2. 排除本轮已展示、正在占用以及处于近期窗口的卡片和主素材。
3. 默认在未学习卡片中选择；没有未学习候选时，选择学习中或需复习的卡片。
4. 在当前优先级内，先选择本轮展示次数最少且仍有候选的顶层章节；次数相同随机选择，再在章节内随机选卡。指定较小范围时使用该范围的直接子章节分组，直属正文单独成组。

章节调度不按片段或卡片数量加权，避免长章节占据大多数抽样机会。范围、学习状态、冷却和章节均衡的优先级固定，测试通过注入随机种子和时钟复现结果。

### 4.2 随机生成新卡

- 从活动资料版本的合格正文中建立素材目录：以同一小节内连续、完整的原文块组成不重叠单元，按证据预算控制长度。目录、标题、习题和低质量内容沿用现有排除规则。
- 一个素材单元保存主原文块集合、章节、页码、正文哈希及资料版本；它是抽样单位，不声称等于完整知识点。
- Rust 先排除已有有效卡片覆盖的主素材、近期学过的素材和其他待发送/运行任务已占用的素材，再按章节覆盖较少优先、同组随机抽取。
- 本地从主素材正文和章节构造有长度上限的检索查询，Python 读取主素材并补充同一所选范围内的相关证据；生成和审核都需检查新问题确实围绕主素材。
- 保留现有证据预算和完整原文块约束。原文不足、超出预算或不适合出题时返回原因；本地最多检查 5 个候选，耗尽后停止。发出模型请求后不自动换素材重试。
- 一次任务最多沿用现有的生成、支持性审核两次模型请求；不增加后台知识点提取调用。失败任务继续计入每日教材任务上限。

初版对已覆盖素材采用保守排除。同一原文的不同知识角度、跨段同义知识点识别留待后续评测，不能把素材去重称为语义去重。

### 4.3 近期窗口与耗尽处理

建议默认排除 **近 7 天展示过，或最近 20 次不同展示事件中出现过的卡片及主素材**，即取两个集合的并集；记录按知识库隔离，切换章节不会绕过近期规则。窗口参数集中配置，首版可先使用固定默认值。

- 展示成功即进入近期记录，快速跳过同样避重；生成成功但没有展示不写浏览事件。
- 素材比较同时检查主原文块是否重叠，防止重叠片段或同素材不同题面立即再次出现。
- 来源不明确的旧卡至少按稳定卡片 ID 避重；能验证的旧引用块用于保守的来源重叠过滤，不猜测其主知识点。
- 取下一张时短暂预留候选，前端确认展示后幂等提交事件；失败或过期释放预留。待发送生成任务沿用 30 分钟预览期限，运行任务在终态或启动恢复时释放占用。
- 列表渲染、刷新、回看上一张、恢复当前卡片，不新增展示事件；主动开始新一轮并再次抽到该卡才计为新展示。
- 无候选时说明原因和数量，提供“开始一轮复习”“扩大章节范围”或“随机生成新卡”。用户主动开始复习可以放宽近期限制，但本轮依然不重复；不自动放宽规则。

生成前使用来源记录减少无效调用，入库时继续使用同库规范化题目唯一约束。若仍生成重复题，返回已有卡片及重复原因，保留已有学习状态，不追加模型调用来凑出新卡。

## 5. 学习状态与存储

| 状态              | 进入条件                 | 后续行为                                 |
| ----------------- | ------------------------ | ---------------------------------------- |
| 未学习 `new`      | 新卡或没有学习记录的旧卡 | 默认优先抽取；仅展示问题、跳过不改变状态 |
| 学习中 `learning` | 未学习卡首次揭晓答案     | 可继续随机学习，并记录揭晓次数           |
| 需复习 `review`   | 用户主动标记             | 可从复习筛选中找到；普通揭晓不会清除标记 |
| 已掌握 `mastered` | 用户主动标记             | 默认随机流排除，可改回学习中或需复习     |

建议新增以下业务表，名称在实现时可调整：

| 表                      | 主要数据与约束                                                                   |
| ----------------------- | -------------------------------------------------------------------------------- |
| `rag_learning_units`    | 知识库、来源身份、版本、章节、主原文块、正文哈希、抽样规则版本；目录可从索引重建 |
| `rag_card_units`        | 卡片到主素材的映射；旧卡允许主素材未知，补充证据仍保存在原快照                   |
| `rag_learning_state`    | 每卡当前状态、首次/最近展示、最近揭晓、展示/揭晓次数、状态更新时间及更新版本     |
| `rag_learning_events`   | 事件 ID、卡片、会话、展示 ID、事件类型、时间、状态前后值；支持幂等写入和撤销     |
| `rag_learning_sessions` | 知识库、章节范围、过滤规则、当前卡片、揭晓状态、恢复信息；本轮集合由事件关联恢复 |

候选占用信息可保存在会话及生成任务元数据中，配唯一约束和到期时间。卡片状态是学习事实来源，素材覆盖由关联卡片状态计算，不另存一套容易冲突的“掌握状态”。

关键一致性约束：

- 展示、揭晓和状态变更采用独立事件 ID，重复点击或命令重试不重复计数；事件、当前状态与会话进度在同一事务更新。
- 使用状态版本防止迟到请求覆盖较新的标记；撤销仅撤销仍然有效的最近一次状态变更。
- 新卡、来源映射和生成任务终态事务保存；创建卡片时初始化未学习状态，不补写学习事件。
- 旧卡迁移为未学习，仅回填可验证的来源字段，不从历史生成时间推测阅读或掌握情况。
- 资料版本变化时，原卡及引用继续固定到旧版本。只有来源身份、定位和正文哈希都能验证一致时复用素材覆盖；无法可靠对应的新素材重新进入候选。
- 普通“清除阅读记录”保持现有范围。新增“重置本知识库学习记录”并明确会清除状态、事件、近期窗口和会话，保留卡片及教材；沿用应用确认对话框。
- 全部数据清理覆盖新增业务表；清理与在途写入沿用持久化门控，并使旧会话请求失效。记录分页读取，不沿用普通最近浏览最多 500 条的淘汰规则来删除学习事实。

## 8. 验收标准

自动化测试使用可控时钟、固定随机种子、临时数据库和 Mock 模型，至少覆盖：

- 范围隔离：不跨知识库或所选章节；排除不合格正文；无卡片、无合格素材、单卡库都有明确结果。
- 抽样规则：优先级相同且各章候选充足时，章节展示次数差不超过 1；长章节不会因片段数量多而占更多机会。
- 近期避重：同时验证 7 天和最近 20 次展示窗口、边界时间、切换章节、重启、小库耗尽、显式复习及主素材重叠。
- 状态语义：展示和跳过不代表已学；揭晓只把未学习转为学习中；掌握和需复习可恢复、撤销；今日统计不重复累计同一卡片。
- 一致性：双击下一张、重复回调、迟到响应、数据库写入失败、预留超时、进程重启不会重复计数或丢失已保存状态。
- RAG：预览不调用模型；生成遵守两次调用及每日预算；依据不足、重复题、版本切换、失败任务不自动重试，不污染学习统计。
- 兼容：旧卡与引用可读，旧卡不虚构学习历史；重置本库记录与全部清理行为正确，迟到写入不会恢复已清空的记录。

桌面验收使用《计算机组成原理》至少 3 个有合格内容的章节。建议真实生成并人工抽查 10 张卡，检查选题围绕主素材、答案与引用相符、章节归属正确；样例数量不足时如实记录原因。关闭网络验证已存卡学习、切换页面和重启恢复，并在 420 × 560、360 × 440 窗口检查布局。

实施完成后运行前端格式、lint、测试和构建，以及 Rust 格式、Clippy、测试和 Python 对应检查。报告实际结果和失败案例，不能用 Mock 通过替代真实生成质量验收。
