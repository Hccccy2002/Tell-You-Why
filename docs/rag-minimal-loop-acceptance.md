3. **APP 操作**：新增“问答与学习”，支持章节范围、任务类型、模型、摘录预览、显式发送、引用展开、原页定位、任务和卡片记录。前端 84 项测试、TypeScript、ESLint 通过。
4. **持久化**：业务数据库迁移至 7，增加 `rag_tasks`、`rag_cards`。卡片与证据快照原子保存，重启可读，同库题目去重，跨库不冲突。任务领取通过 SQLite 条件更新防止重复执行；日预算统计已发起任务。故障注入验证事务回滚，通用数据清理行为覆盖回归。
5. **整体验收**：Python 54 项通过、Ruff 通过；前端 84 项通过、TypeScript 和 ESLint 通过；最终 v8 的 Rust 全量 88 项通过、2 项显式跳过。共 226 项常规测试。新增输出截断回归验证只请求一次、保留用量且不发布学习内容。跳过项分别为原有系统凭据写入测试和需要显式启用的真实模型验收；后者另行运行，结果如下。

对本批次发布的 6 份回答/卡片逐条复核，27 处引用均等于对应证据块的完整原文，未发现超出引用的实质性事实。原文中的条件、标点和空格由程序保留；模型只选择引用编号。范围、页码和源块身份还经过证据层检查。这是固定回归样本的结果，不能证明任意问题的准确率。

诊断和修复过程保留如下：

- v1–v3 非思考生成/审核曾漏检 Cache 因果扩写与循环解释；只加强提示词仍不足以可靠解决。
- v4 启用 DeepSeek 思考模式；审核预算 4000 Token 出现截断，随后提高为 8192 Token。
- v5/v6 的完整批次分别为 9/10 符合预期，另有结构或引用协议失败；v5 的 APP 总线学习卡也失败，记录保留。后续改为模型仅选择证据编号，程序填入完整原文，丢弃模型多余的旧 quote 字段。
- v7 的单项 CPU 卡通过；2026-09-09 的完整批次被用户中断，只保留 1 项完成结果，不算完整验收。
- 2026-09-10 v7 完整批次为 8/10 符合预期，总线问答与 Cache 问答各出现一次生成截断：3000 Token 全部被用于思考。v8 将 DeepSeek 生成预算提高至 8192 Token，完善失败提示并增加不重试、不发布的回归；随后完整批次 10/10 符合预期。

当前 DeepSeek 生成/审核分别使用 low/high 思考强度，各最多 8192 Token、90 秒；每任务最多两次调用，无自动重试、供应商切换或自由问答回退。旧待发送任务因协议版本变化需重新预览；已完成记录仍可读取。不保存模型思考正文。
