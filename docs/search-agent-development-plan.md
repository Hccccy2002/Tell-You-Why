# 智谱搜索 Agent 开发计划

日期：2026-09-21。状态：P0–P3 已完成开发及阶段测试。P0–P2 包含真实智谱接口与 Windows 桌面重启回看；P3 包含学习中心真实联网集成、来源复用与收藏验证，以及前后端自动化回归。按用户后续要求，最初提前提供了 APP 内的智谱凭据设置。详见 [P0–P2 验证记录](validation/search-agent-p0-setup.md)和 [P3 验证记录](validation/search-agent-p3.md)。P4、P5 尚未开发。

设计依据：[搜索 Agent 设计方案](search-agent-design.md)。下文保留阶段计划；阶段是否通过以验证记录为准。

## 1. 交付顺序与工作量

以下为一名熟悉本项目的开发者的工作量估算，含阶段测试与评审；不包含账号开通等待、第三方故障或额外安装包发布流程。阶段按依赖推进，可根据实际接口验证结果调整。

| 阶段              | 工作内容与交付物                                            | 估算       | 退出条件                                                         |
| ----------------- | ----------------------------------------------------------- | ---------- | ---------------------------------------------------------------- |
| P0 接口验证与契约 | 官方接口核验、真实账号样例、冻结字段和错误映射              | 0.5–1 人日 | 至少取得成功、空结果、鉴权错误样例，明确引擎、计费和字段缺失行为 |
| P1 搜索基础设施   | SearchProvider、智谱适配、独立设置/凭据、数据迁移、测试连接 | 1.5–2 人日 | 桌面端可配置和测试，Key 不泄漏，旧数据库可升级                   |
| P2 卡片追问闭环   | 路由、搜索、证据、回答、引用 UI、保存与取消                 | 2–3 人日   | 普通/划词追问可联网，回退不重复搜索，重启仍可回看来源            |
| P3 陪伴学习接入   | 自由问题、再次解释、预算、暂停恢复、学习收获来源            | 2–3 人日   | 不推进原学习步骤，不覆盖暂停结果，旧会话可恢复                   |
| P4 MVP 质量与交付 | 冻结评测、真实模型回归、故障/预算验收、使用文档             | 1.5–2 人日 | 达到下述质量门槛，所有回归与桌面冒烟通过                         |
| P5 扩展输出入口   | 近期知识卡、学习讲解搜索、教材联网拓展                      | 3–5 人日   | 每个入口都有独立范围、来源和时间语义，并通过专项验收             |

MVP（P0–P4）约 7.5–11 人日；包含 P5 的完整扩展约 10.5–16 人日。若改为直接接入智谱托管 Search Agent，应先重做 P0，再评估会话、引用和运行控制的成本。

## 2. P0：确认接口与适用边界

1. 重新核对当前中国区 Web Search REST API：URL、鉴权、引擎 ID、query 长度、count 范围、时间枚举、域名限制、摘要规格和响应大小。
2. 确认账号是否开通对应引擎、实际单价、限流、并发、测试连接计费方式；不将其他订阅套餐或 MCP 权益默认当作 REST API 权益。
3. 用公开且不敏感的查询获得脱敏样例，记录响应 ID、结果数组、URL、摘要、资料日期及各字段可空情况。
4. 检查强制搜索语义：如果供应商有自行判断是否检索的设置，验证“用户要求联网”的请求不会被静默跳过。
5. 验证 401/403、余额不足、429、超时、5xx 的实际错误格式；难以安全触发的故障使用契约替身测试，并注明非实测。
6. 确认 request_id 是追踪标识还是确实支持幂等；取消本地 Future 不代表供应商终止计费。
7. 冻结 20–30 个代表性题目用于接口探索，和后续留出评测集分开；比较候选引擎质量后确认默认引擎。

产物：接口契约、脱敏 fixtures、默认策略建议、账号/价格核验记录。没有账号时可继续 Mock 开发，但不能宣布真实联网验收完成。

## 3. P1：搜索基础设施

拟新增模块以 `src-tauri/src/search/` 为边界，避免继续膨胀通用 `commands.rs`：

| 文件（拟新增）            | 职责                                           |
| ------------------------- | ---------------------------------------------- |
| `mod.rs` / `types.rs`     | SearchProvider trait、请求/结果/配置、错误枚举 |
| `zhipu.rs`                | 智谱参数映射、HTTP 请求和响应规范化            |
| `policy.rs`               | 搜索次数、超时、模型调用和父会话预算联动       |
| `routing.rs` / `agent.rs` | 时效判断、必要规划、检索与补搜编排             |
| `evidence.rs`             | 证据清洗、日期、去重、引用校验                 |
| `store.rs` / `schema.sql` | 配置、运行、证据快照与缓存                     |
| `commands.rs`             | 窄 Tauri 接口与 runId 归属检查                 |

修改范围：

- `providers/mod.rs`：复用或抽出受限 HTTP 基础能力；为搜索建立明确的目标策略，不把智谱搜索当作生成模型注册。
- `secret_store.rs`：复用现有系统凭据接口；搜索配置使用独立 credential_ref 和失效状态。
- `db.rs`、`lib.rs`：新增迁移、初始化与命令注册，前端 API 通过受限 IPC 使用。
- `src/screens/ModelSettingsScreen.tsx`：增加联网搜索设置；复用现有 Key 保存、替换、删除交互。
- `src/lib/search.ts`（新增）、`src/types.ts`：类型、调用、配置状态和浏览器预览替身。

验收：固定查询测试可用；错误可辨认；日志、导出、数据库中没有 Key；不接受任意主机和重定向；搜索未开启时无网络请求；数据库重复迁移安全。

## 4. P2：卡片追问的完整闭环

按照“先检索、再回答、校验后持久化”接入 `commands.rs::ask_follow_up_inner`。

1. 每次提交生成 requestId/runId，解析用户模式、时区、短上下文和问题指代，先保存运行状态。
2. 路由稳定知识走旧路径；时效问题调用 Search Agent。查不到足够资料时生成明确的不足结果。
3. 检索放在现有供应商回退循环之前；将不可变证据包交给新回答适配方法，回退复用同一份证据。
4. 扩展 `FollowUpResponse` / 前端结果类型，保留现有文本字段并增加可选引用块、快照 ID、时间与状态。
5. 回答校验后在同一业务事务中保存结果及证据关联；失败或取消结果不能伪装为成功回答。
6. `KnowledgeCardView.tsx` 增加来源折叠区、进度和取消；关联 `App.tsx`、`src/lib/api.ts` 的参数及状态。
7. 追问历史重新加载、原卡切换、重复点击、Key 被删除和全部清除都覆盖状态竞争测试。

应特别验证：划词提问的展示文本与实际请求文本仍按现有逻辑保存；新搜索词不能把隐藏的多余上下文发送给智谱；原卡可信状态和正文不因追问被改写。

## 5. P3：陪伴学习接入

已实现：学习中心自由追问、问题反馈“还没懂”后的再次解释、疑问重开、单次联网核查、进度与暂停恢复、来源回看及学习收获。异步搜索由 `study_search.rs` 在父会话检查点内执行，复用 P2 的智谱适配器、规划契约、引用校验与来源组件。旧会话继续使用 `study-companion-v1`，新增可选字段默认兼容，已保存的旧工具动作按原契约完成。

以下保留原阶段设计依据：

当前 `study_agent.rs` 在存在 pending question 时只允许调用 `answer_question`，普通工具执行器也是同步路径。建议在该最终回答之前加入异步搜索准备阶段，保持现有“一个回答留在当前步骤”的约束。

1. `study.rs`：为问题/回答/运行增加可选搜索状态、证据关联和策略快照；旧 JSON 缺字段时正常加载。
2. `study_commands.rs`：继续、暂停、结束、再次解释时同步管理搜索运行，沿用当前执行锁和持久化保护。
3. `study_agent.rs`：在 `answer_question` 前完成检索；模型正文与引用字段经过校验后再提交。
4. `study_store.rs`、疑问与学习收获相关逻辑：保存正文时保留证据关联；再次解释可以复用仍有效的证据，明确要“最新”或证据过期时重新查。
5. `harness/policy.rs` 及必要的通用控制层：把搜索 HTTP 尝试、额外模型请求和主动耗时纳入父会话；搜索失败也不能免计尝试。
6. `StudyPanel.tsx`、`src/lib/study.ts` 等：展示进度、来源和资料时间；暂停后清理旧请求的可见更新权限。

旧会话兼容策略需明确：继续按旧提示版本运行直到会话结束，或做有版本的兼容迁移。不能只修改全局提示版本，从而让所有旧会话触发当前的版本不匹配检查。

P3 暂不要求把网页搜索变成自由调用的通用工具；到 P5 扩展讲解步骤时，再将 `search_web` 作为严格参数和权限约束的异步工具开放。两种入口调用同一个搜索核心。

## 6. P4：验证与 MVP 交付

### 6.1 自动化测试

使用现有 Rust Mock Transport、Vitest 和 Testing Library，不依赖付费接口完成普通 CI。

| 层级       | 必测行为                                                                        |
| ---------- | ------------------------------------------------------------------------------- |
| 智谱契约   | 字段缺失、空结果、日期异常、畸形 JSON、响应过大、鉴权、限流和超时               |
| 路由       | 显式和隐式时效、稳定知识、上下文指代、不同模式、午夜跨日与系统时区              |
| 引用       | 伪造 ID/URL/引文拒绝，只有资料时间才作为发布日期，PDF 和网页编号不混淆          |
| 执行控制   | 总共最多 2 次搜索尝试，模型回退不重复搜索，重试遵守总预算，重复提交不重复启动   |
| 并发与恢复 | 取消后的迟到响应、重启中的未知请求、权限撤销、数据库写失败、Key 删除和清除数据  |
| 持久化     | 旧 DB 升级、旧会话加载、来源历史恢复、缓存过期不破坏证据快照、引用删除语义      |
| 界面       | 来源折叠/打开、时间未知、失败操作、360 像素布局、键盘可操作、状态不串到其他卡片 |

### 6.2 人工内容评测

建议另建 80 题评测集：稳定知识 15、显式时效 20、隐式时效 15、近期技术版本 10、旧闻/冲突/无答案 10、混合与多轮指代 10。预先分开开发与留出部分；每道事实题记录查证日期、适用地区、权威来源、必要结论和允许“不足”的条件。

发布前建议门槛，均为目标而非当前测量结果：

- 时效题搜索召回率至少 95%，明确要求联网的题目在允许联网时全部路由到搜索。
- 稳定知识题不必要搜索率不高于 10%，人工路由分歧单独记录。
- 来源 ID/URL 绑定校验通过率 100%；人工抽查关键结论的证据支持率至少 95%。引用存在不算语义正确。
- 对评测中“有充分资料可回答”的题目，当前事实正确率和有效回答率分别至少 90%；不能靠全部返回不足取得高分。
- 空结果、过期资料和冲突不足场景无编造的最新事实；未人工复核的题目不能计为正确。
- 所有离线故障和边界测试通过；分别公布成功回答、部分回答、证据不足、技术失败及未复核数量。
- 真实搜索阶段 P95 初始目标不超过 20 秒；端到端完成 P95 目标不超过 60 秒。测试至少记录 50 次真实运行、网络条件、引擎、模型、缓存命中情况；超出目标则调整方案或披露，不把硬超时当成性能达标。

自动判断引用结构、人工判断结论与时间适用性。模型评分仅作辅助，不作为唯一通过标准。

### 6.3 项目验证和产物

按受影响模块运行 Rust 测试与前端测试；合入前执行 `npm.cmd run lint`、`npm.cmd test`、`npm.cmd run build`、`cargo fmt --check`、`cargo test`，Rust 命令在 `src-tauri` 下执行，并按仓库现行规范补充严格检查。

浏览器演示不能代替 Windows 桌面验证。至少在桌面完成配置 Key、一次真实检索、来源打开、取消、重启回看、旧会话继续、无网络和小窗口布局冒烟。

产物：功能源码与迁移、契约样例、测试、搜索使用指南、人工评测记录、验证说明。开发完成后再按发布任务范围准备安装包；源码可运行不等于安装包已发布。

## 7. P5：覆盖更多输出

| 扩展项         | 核心改动                                                                                     | 专项验收                                                             |
| -------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 近期知识卡     | `providers/mod.rs`、`content.rs`、卡片存储/视图新增基于证据的生成模式；保存 asOf / expiresAt | 过期内容有提示；随机稳定卡片不被迫搜索；后台不自行请求               |
| 学习讲解与计划 | 为 `study_agent.rs` 添加受限异步 `search_web`，复用预算和来源处理                            | 关键时效陈述有来源；练习依然等待真实作答；不中途改分                 |
| 教材联网拓展   | `rag_commands.rs`、`rag.rs`、`learning_generation.rs` 和知识库界面增加外部证据分支           | 教材页码与网页来源明确区分；外部结论不伪装为教材原文；用户可只用教材 |
| 复习补充阅读   | 复用搜索服务生成独立拓展内容                                                                 | 不自动改写教材评分、已提交答案或历史掌握状态                         |

新入口沿用查询最小化与资料时间规则，单独评测。长篇深度调研、网页全文抓取、多引擎自动比较和直接托管 Search Agent 属于另行评估的能力。

## 8. 主要风险及对应工作

| 风险                               | 对应措施                                                            |
| ---------------------------------- | ------------------------------------------------------------------- |
| 搜索结果旧、摘要不足或来源互相冲突 | 保存资料时间，补搜受预算约束；不足时缩小结论范围                    |
| 加入搜索后延迟明显增长             | 常见问题先规则路由，缓存、少量结果和可取消状态；以真实 P95 决定参数 |
| 追问引用只存在内存                 | 回答与证据关联持久化，重启和收藏回看验收                            |
| 恢复导致重复计费或总预算被绕过     | 发请求前预留尝试，未知请求不自动重放，父子预算共同限制              |
| 旧会话被提示版本变化阻断           | 设计有版本的兼容与恢复策略，增加真实旧快照测试                      |
| API 变更或候选引擎不可用           | P0 冻结契约并留适配层；明确错误，不静默切到更贵引擎                 |

建议按“独立智谱搜索 + 保留现有回答模型 + 先完成追问和陪伴学习”开展后续开发。具体单价、默认引擎和性能参数以 P0 验证记录为准。
