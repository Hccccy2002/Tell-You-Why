# Harness v2：统一工具执行与底层取消

本轮完成 v2 路线中的第 1、2 阶段。运行版本为 `review-harness-v2`，工具契约版本为 `review-tools-v2`；系统提示词继续使用 `review-agent-v3`。故障回放与真实模型对照评测尚未纳入本轮。

## 在 APP 中使用

入口仍为 **PDF → 打开教材 → 复习 Agent**。题目数、教材依据要求与完成验收沿用第一版。

点击“暂停复习”后，正在执行的教材版本检查或检索会收到取消信号。程序清理本次调用的 Python 进程及其子进程，确认退出后显示暂停；已完成的步骤保留，待执行工具可在继续时重新执行。取消后到达的结果不会加入原文列表、产生新的模型请求或提交记分。

执行记录新增“校验教材版本”“重试只读工具”，步骤详情包含工具权限、尝试次数、错误码及 `process_cleanup` 状态。无法确认进程清理时，任务以 `process_cleanup_failed` 停止，不自动重试。

## 统一工具契约

`harness/tools.rs` 的注册表提供模型可见的参数定义，同时作为运行前验证依据。参数验证只实现本项目注册表使用的 JSON Schema 词汇；业务处理器还会检查来源编号、章节、题目状态及实际提交。

| 工具                    | 业务权限   | 单次等待上限 | 每个调用编号最多自动尝试 |
| ----------------------- | ---------- | ------------ | ------------------------ |
| `get_learning_progress` | 只读       | 5 秒         | 1 次                     |
| `search_textbook`       | 只读       | 60 秒        | 2 次                     |
| `read_source`           | 只读       | 5 秒         | 1 次                     |
| `save_review_question`  | 写复习状态 | 5 秒         | 1 次                     |
| `record_quiz_result`    | 写复习状态 | 5 秒         | 1 次                     |

实际等待时间取工具上限、任务策略上限及剩余执行时间的最小值。检索仅对超时或明确的临时依赖错误自动重试；参数、权限、引用、范围、结构和未知依赖错误不自动重试。每次尝试都计入任务工具预算并持久化，失败尝试在执行记录中可见；同一次模型工具调用只收到一个最终结果。

`control.tool_permissions` 默认允许读取与写入复习状态，由程序配置并随任务保存；模型参数不能修改权限。这里的“只读”指不会改变学习业务数据，检索证据和操作记录仍保存到任务检查点。

错误使用明确的 `error_code`、可读消息与 `retryable` 字段，不根据中文字符串判断新调用的错误类别。业务处理先操作候选状态，成功且结果长度合规后才交给检查点事务；失败不会留下已追加的部分原文。现有真实提交验证与幂等记分事务继续生效。

SQLite 仍使用短同步事务，取消标记和记分提交按事务顺序决定先后；已经完成的提交保留。取消不是撤销历史提交，也不强制中断正在执行的 SQLite 调用。

工具参数最多 32 KiB，工具返回结果最多 64 KiB。原始 Python 请求最多 64 KiB、标准输出最多 2 MiB；标准错误持续排空但不保存或发送给模型，避免日志填满管道后阻塞清理。

## 进程与取消机制

每次受控 Python 调用拥有一个匿名 Windows Job Object，并设置关闭句柄时结束进程组。进程以暂停状态创建，加入进程组后再恢复其初始线程；Python 启动脚本还会等待输入信号。这样虚拟环境启动器及后续创建的子进程从执行开始就受同一进程组管理。

独立工作线程持有进程、标准输入输出与进程组句柄，每约 20 毫秒检查取消和截止时间。异步等待被暂停或超时打断时，作用域发送取消信号并等待工作线程确认清理，而不是只丢弃等待。进程组终止后检查活动进程数量，并等待已取得的进程句柄进入退出状态，随后回收直接子进程及管道线程。作用域被直接丢弃也会发出取消信号。

清理确认最多等待 5 秒。只有确认清理后才允许当前工具重试；清理时间也计入执行时间预算。因此等待上限之外可能存在有限的清理耗时，不代表严格的 CPU 使用时间限制。

受控资料执行器只允许 `evidence`、`learning_version`、`learning_units`。复习开始前的版本校验已移到可取消的任务状态内；创建任务或读取知识点目录时的独立资料读取也使用有截止时间的作用域。PDF 导入任务继续使用自身的持久化作业与暂停协议，不归复习调用的进程组管理。

这是本地进程生命周期管理，不是通用安全沙箱；远程模型已经接受的请求仍不能由本地暂停撤销。恢复和费用未知预留规则沿用 [第一版说明](harness-v1-guide.md)。

## 自动验证

第一阶段通过测试后再实施第二阶段，结果见 [开发记录](harness-v2-development.md)。Windows 进程测试需要项目的 `rag-service/.venv/Scripts/python.exe`，使用临时目录中的受控脚本，不需要加载模型或个人教材。

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline harness::process_tests -- --nocapture
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline harness::cancellation_tests -- --nocapture
```

覆盖父子进程取消、丢弃异步等待、截止时间、阻塞输入、标准错误排空、父进程先退出、过大输出、真实 Python 接入复习后暂停恢复、迟到结果拒绝，以及生产资料适配器的 JSON 协议和操作权限。

测试证明受控环境下的执行与持久化行为；没有新增真实模型请求，也不能据此声明内容准确率或第三方推理库所有故障均已覆盖。
