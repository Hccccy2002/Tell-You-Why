# 教材问答与单张学习卡

本阶段在已有 PDF 知识库上接入 RAG。使用当前教材索引，不需要重新 OCR 或重新下载嵌入模型。

## APP 操作

1. 按 [README 源码启动](../README.md#源码启动)打开当前应用，准备 PDF 环境后点击 **PDF**，选择并导入自己的资料。历史《计算机组成原理》案例不随源码分发。
2. 打开 **问答与学习**，选择章节范围。
3. 选择 **教材问答** 或 **生成一张学习卡**，选择已经配置并通过连接测试的模型通道。
4. 输入问题或学习主题，点击 **检索并预览摘录**。这一步在本机检索并保存待发送任务，不调用云端模型。
5. 核对摘录及目标供应商，点击 **发送摘录并回答 / 生成学习卡**。
6. 查看回答及逐条依据；点击引用可以打开生成时对应版本的 PDF 页面。
7. 在 **任务记录** 中重新打开回答，在 **已存学习卡** 中读取已保存的卡片。两者均按教材隔离并分页。

未配置生成模型时，请在 APP 菜单中的模型设置配置 DeepSeek 或 Kimi 并通过连接测试，然后刷新。请不要把 API Key 填入问题框。

## 本地和云端的范围

PDF、OCR、嵌入和检索继续在本地运行。云端只接收问题、章节标题、预览中的原文摘录，以及需要检查的生成草稿；不发送 PDF 文件、文件路径、其他知识库或旧对话。API Key 由 Rust 从系统凭据库读取，Python 不持有密钥。

每个显式生成任务最多两次请求：生成草稿一次、支持性检查一次。DeepSeek 生成及检查输出上限均为 8192 Token；Kimi 生成上限 3000 Token、检查上限 8192 Token。每次请求超时 90 秒。DeepSeek 生成和审核启用思考模式，分别使用 low 和 high 强度，输出预算包含思考消耗。真实测试发现 3000 Token 可能全部用于思考而未输出答案，因此提高 DeepSeek 生成预算。供应商返回的用量保存在任务中，未返回时明确显示未知。没有自动重试、供应商切换或自由问答回退。参数依据 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)核对（2026-09-09）。

每日教材任务数上限沿用设置中的每日生成限制，单独统计已发起的教材任务；失败任务也计入，避免失败重试绕过预算。此计数与旧随机卡片的成功生成数量分开。预览有效期为 30 分钟，修改问题、章节或模型后应重新检索。APP 更新生成规则后，旧待发送任务需要重新预览；已完成的历史结果仍可读取。

## 内容检查与保存

- 证据取自索引中已标记可用的文本；附录中的合格文字保留。低质量文字、习题、参考文献以及未解释的图表、公式继续使用原有排除规则。
- 证据去除重叠片段造成的重复源块，最多 12 个完整原文块、10000 字。可补充同一小节的相邻文字，不截断块内条件；预算不足的块计入遗漏数量。
- 来源编号、页码、坐标、原文版本由程序维护。模型只选择证据编号，程序从已验证的证据包填入该编号的完整原文块，避免模型抄录时改动标点、空格或文字。原文块受证据包总计 10000 字的上限约束，保留其中的条件和例外。
- 程序拒绝未知证据编号、重复引用和额外来源字段；如模型仍返回旧协议的 quote 字段，先丢弃该字段，再从已验证的证据编号填入原文，绝不直接采用模型抄录内容。另一次模型请求逐条说明依据支持情况，同时检查范围、例外和问题覆盖。每项结论只能由它自己的引用编号指向的原文支持，不能借用未引用的内容。审核请求按编号读取原文，不重复发送每条结论的整块摘录。审核结论存入任务用量记录中的 verification 字段供验收排查，不保存模型的思考内容。模型审核并不等于人工校对，重要细节仍需对照原文。
- 回答、证据快照、实际模型及用量保存在业务 SQLite 的 `rag_tasks`。成功学习卡和快照在同一事务写入 `rag_cards`，不受原有 30 张动态缓存淘汰影响。
- 同一本书的相同规范化题目只保存一张学习卡；不同书分别保存。随机抽样、近期素材避重及掌握状态已接入，见 [随机学习使用说明](random-learning-guide.md)。近义知识点识别及批量卡片尚未实现。
- 正常切换界面时，运行中的任务由 Rust 完成保存。完全退出 APP 会中断云端任务；重开后会将遗留运行任务标为中断失败，不会自动重发。先刷新核对，必要时重新检索并显式发起新任务；此前请求可能已经产生费用。
- 通用设置的“清除历史”保留教材学习记录；“清除全部本地数据”会清除教材任务和学习卡，但 PDF 知识库文件仍保留，符合此前资料清理边界。

## 开发验收

常规回归：`npm.cmd test`、`npm.cmd run build`、`npm.cmd run lint`、`cargo test --offline --manifest-path src-tauri/Cargo.toml`、`python -m pytest rag-service/tests -q`。

真实教材证据集：

```powershell
rag-service\.venv\Scripts\python.exe rag-service/scripts/evaluate_evidence.py --data data --output tmp/rag-reports/evidence-final.json
```

该脚本复用已标注的 30 个检索任务并增加 20 个章节范围任务，只测证据覆盖及隔离，不把命中率当作回答正确率。真实模型验收另有显式启用的 `rag_live_textbook_acceptance` 测试：使用指定的测试资料、已配置通道和独立测试数据库；正常测试不会发起外部请求。

本机 Python、模型和源码仍未封装为可在无开发环境电脑上安装的完整运行包。
