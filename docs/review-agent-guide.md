# 复习 Agent

入口：**PDF → 打开教材 → 复习 Agent**。选择章节、输入复习目标并点击“开始复习”。Agent 读取学习记录，按需要检索与阅读原文，讲解知识点并保存选择题；用户提交答案后，Agent 记录结果并继续讲解，最多三题。可指定本次题目数，并选择“必须引用教材”。运行预算、上下文管理及完成验收见 [Harness v1](harness-v1-guide.md)。

模型通道沿用现有设置，使用当前已就绪通道列表的第一个通道。打开页面或浏览历史不会请求模型；开始、提交答案和继续复习会执行模型请求。一个任务固定使用创建时的通道、区域、模型、教材版本与章节，设置或教材版本变化后应开始新任务。

相关原文默认折叠，可展开查看并跳转到原 PDF 页。题目显示关联的原文编号；没有原文的题目标记为“模型补充 · 暂无原文依据”。参考答案与解释在提交并记录结果后展示，模型内容仍需对照教材。

## Agent 与工具

模型通过原生 function calling 自主决定下一步，Rust 执行工具并把结果加入下一轮模型上下文。检索词、是否换词重试、阅读哪段材料及练习内容由模型选择。

| 工具                    | 实际作用                                       | 主要边界                        |
| ----------------------- | ---------------------------------------------- | ------------------------------- |
| `get_learning_progress` | 读取当前范围的知识卡状态和近期真实答题结果     | 无记录不等于已掌握              |
| `search_textbook`       | 调用现有 Python RAG 检索，支持关键词或混合检索 | 书籍、版本、章节由服务端固定    |
| `read_source`           | 分段读取本次检索返回的原文块                   | 已返回的编号，每段最多 2,000 字 |
| `save_review_question`  | 保存选择题、参考答案、解释及原文关联           | 同时最多一道未完成题目          |
| `record_quiz_result`    | 根据用户实际提交的选项记录结果                 | 模型不能提交选项或自行声明分数  |

回答错误时，关联的已有知识卡标记为“需复习”；正确的新卡进入“学习中”，不会因为一次答对自动判定为掌握。没有关联卡片时仍保存复习题及答题记录。判分只比较用户选项与模型生成的参考答案，知识正确性由质量评测另行检查。

## 长期复习

页面顶部显示当前教材和所选章节的到期数量、已练习知识点数和最近答错的知识点数。
点击“复习到期知识点”，每轮选择一个已经到期的知识点，优先处理最近答错的内容；
Agent 重新检索教材、出题并等待提交。没有到期内容时按钮禁用，仍可输入目标开始普通复习。
展开“知识点与复习时间”可查看实际答题次数、答对次数和下次时间。

排期由程序计算：答错后 10 分钟再次复习；连续答对按 1、3、7、14、30、60 天安排，
之后保持 60 天上限。答错会重置连续答对次数。它是可解释的简易练习规则，
没有经过用户实验验证，也不等于遗忘概率或掌握程度预测。所有时间以 UTC 秒存储，界面用本地时间显示。

`get_learning_progress` 返回持久化知识点及排期；模型通过 `save_review_question.memory_id`
关联已有记录，不能指定分数或复习时间。到期复习必须带回指定编号，改写问题不会创建重复知识点。
普通复习没有明确关联时，按教材、版本、章节、关联卡片与规范化主题生成标识；
同义但不同名称的主题仍可能成为不同记录，目前没有语义合并。

迁移 10 新增 `review_memory` 和 `review_memory_events`，按历史真实提交回填，
优先使用原执行追踪中的判分时间；没有追踪时使用任务保存时间。重复工具执行、恢复和重复提交
不会重复累计。未提交、跨教材版本或章节的记录不会被当作本轮掌握度。
清除全部数据会一并清除这些表；清除普通阅读历史保留复习安排。

## 持久化与恢复

数据库迁移 9 新增 `review_runs`。模型请求前、工具执行前后及用户提交时保存检查点。工具带来的学习状态变更与任务检查点在同一事务中提交，继续任务不会重复记分。重复提交同一答案幂等，覆盖已提交答案会被拒绝。

任务状态包括 `ready`、`running`、`waiting_answer`、`paused`、`failed`、`stopped`、`completed`。可恢复故障可点击“继续复习”；终止状态需开始新任务。重启应用后，执行中的任务恢复为暂停状态，保留已完成步骤。近期复习可查看当前教材的最近 20 次任务。

暂停会结束异步等待，并清理本次受控资料调用的 Python 进程组，确认退出后再暂停；已经接受的远程模型请求无法撤销。每次继续最多执行六轮模型决策；每个任务最多 16 次模型请求、32 次工具尝试、三道题，并受用量与执行时间预算约束。临时模型故障最多自动重试一次，不跨供应商；只读检索的超时或明确临时故障最多自动重试一次，写入工具不自动重试。具体工具规则和进程管理见 [Harness v2](harness-v2-guide.md)。清除全部本地数据时同步删除复习任务；清除普通阅读历史保留复习任务。

## 执行追踪

展开“执行记录”查看步骤，点击“导出 JSON”后通过 Windows 保存对话框选择本地文件。记录与任务一同保存在 SQLite 中，包含：

- 任务 ID、模型、教材版本、提示词版本和复习目标。
- 按序排列的模型请求、工具调用、用户提交和状态变化。
- 时间、耗时、完成/失败/中断状态、工具参数摘要、原文编号与页码。
- 模型返回的输入、输出、总 token 数；缺失用量标记为未知，并显示覆盖了多少次请求。
- Harness 策略与预算占用、上下文保留与省略数量、完成检查及停止原因。预算估算与供应商实际 token 用量分别展示。

失败记录保留错误类别；网络中断记录保留面向用户的错误信息。重启恢复时，未完成事件标记为中断，此事件的耗时是从开始到恢复的墙钟时间，不能当作模型实际计算时间。未收到用量的失败请求可能仍产生费用；不根据未知用量推算零费用。

导出的结构化记录不包含系统提示词、模型隐藏推理、原始供应商响应或待答题的答案键。为支持后续模型上下文，内部检查点保留模型消息；该内部消息列表不会通过界面或追踪导出返回。追踪包含目标、检索词和教材标识，分享前应检查其中的个人信息。
