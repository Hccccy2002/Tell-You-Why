## 后续修正：保留搜索资料供模型判断时效（2026-09-21）

用户反馈“今天上海天气如何”返回固定的资料不足提示。初版在本地要求来源必须有可解析且落在时间范围内的 `publish_date`，导致有目标日期信息的摘要也可能全部被删除。此处修正取代前述 P1/P2 初版的本地发布日期硬筛选策略：

- 继续向智谱发送原时间条件，保留有效 URL、标题和摘要；不再因网页发布日期缺失或较旧而丢弃整条资料。无法解析或未来的发布日期显示为未知，已有可用日期仍如实保存。
- 回答模型结合标题、摘要中的事件日期、更新/观测时间、预报有效期判断时效。天气问题核对城市和目标日期，区分预报与实况，禁止从检索时间推断正文时间。
- 搜索缓存版本升级，避免复用旧日期策略产生的空缓存。来源绑定、取消、次数与时间预算保持原逻辑。
- 真正没有可用来源时显示“搜索提示”，不再在界面署名为 DeepSeek / Kimi 整理的回答。

自动化验证：Rust 搜索专项 20 项通过、2 项显式真实账号测试跳过；前端追问及来源相关 23 项通过；Rust 格式和严格 Clippy、ESLint、TypeScript 与生产构建均通过。构建仍有既有的单包体积提示。回归包含日期未知的资料送入模型、旧发布日期但正文含当日预报、来源持久化，以及真正空结果不调用回答模型。

桌面真实复验：在用户原环境的开发版提交一次“今天上海天气如何”，检索时间 `2026/9/21 14:04:29`。返回并保留 8 条来源，界面中的结构化发布日期均为“日期未知”，但摘要包含明确的 2026 年 9 月 21 日报道或该日的预报。DeepSeek V4 Pro 成功整理天气回答，引用 W1、W6、W7，来源可展开；不再走固定空结果兜底。此项验证证明本次问题的资料能进入整合流程，不代表所有实时问题均能获得充分资料。

## 后续修正：原文链接为空不等于搜索内容为空（2026-09-21）

用户反馈“介绍几个今天的科技新闻”仍被提示没有资料。此次先捕获实际请求和响应，排查供应商输出和本地解析，不按问题主题增加逻辑分支。

真实复现记录（2026-09-21 14:17:07，Asia/Shanghai）：

| 项目                              | 实际值                       |
| --------------------------------- | ---------------------------- |
| HTTP 状态                         | 200                          |
| 引擎                              | `search_pro`                 |
| 搜索词                            | `2026年9月21日 科技新闻`     |
| 时间范围                          | `oneDay`                     |
| `search_result` 条数              | 5                            |
| 非空 `content` 条数               | 5                            |
| 五条摘要长度（字符）              | 627 / 212 / 923 / 1026 / 872 |
| 非空 `title`、`publish_date` 条数 | 各 5                         |
| 空 `link` 条数                    | 5                            |

根因是解析器此前遇到空链接就跳过整条结果，五条有正文的摘要因此全部丢失。供应商本次没有返回空内容，APP 的提示不准确。原始公开响应保存在本地 Git 忽略目录 `tmp/search-agent/captured-response.json`，不包含请求头或完整 Key；临时的一次性捕获代码已移除。

通用修复：

- 来源 URL 可为空，摘要仍送入回答模型并随回答持久化。来源区保留标题、正文和日期，无可打开链接时显示“智谱搜索摘要 / 原文链接不可用”，不补造链接。
- 缺少标题时使用明确的“智谱搜索摘要”标签；不可打开或不安全的 URL 不成为按钮，摘要仍按不可信文本处理。显式域名限制继续严格执行。
- 真正的空列表、结果缺少正文和来源范围过滤分别处理，后两者显示返回条数及原因，不混同为接口没有输出。
- 统一时效判断提示词，移除天气专用表述；搜索缓存版本升级，旧历史中带字符串 URL 的记录兼容读取。
