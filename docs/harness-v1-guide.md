# Review Harness v1

本页保留第一版设计与验收口径。当前工具执行与 Python 取消能力已升级，见 [Harness v2](harness-v2-guide.md)。

Harness v1 为教材复习 Agent 增加运行约束、上下文组装和完成验收。版本为 `review-harness-v1`，新任务使用提示词版本 `review-agent-v3`。五个现有工具、真实用户提交与 SQLite 事务继续由 Rust 执行。

## 在 APP 中使用

1. 进入 **PDF → 打开教材 → 复习 Agent**，选择目标与章节。
2. “本次题目数”可指定 1、2、3 题，默认由 Agent 安排 1–3 题。指定数量后，实际完成这些题目才允许任务完成。“复习到期知识点”仍每轮处理一个知识点、一题。
3. “资料依据”默认允许模型补充；选择“必须引用教材”后，无原文编号的题目会被工具拒绝。材料不足时可能无法完成任务。
4. 逐题作答。模型提前结束或忘记记分时，程序给出具体待办，最多自动修正两次。
5. 展开“执行记录”，查看预算占用、上下文保留情况与逐项完成检查；“导出 JSON”包含同一份诊断信息。

预算耗尽、连续无进展或一致性检查失败会显示“本次复习已停止”，此时需要开始新任务。暂停、执行片段结束及可恢复故障可继续；是否允许继续以服务端计算结果为准。

## 运行策略 RunPolicy

策略保存在每个任务的 `control.policy`，暂停、继续及重启不会重置。首版界面只提供题目数与教材依据选项；运行阈值由代码默认值定义。

| 约束         | 默认值                | 行为                                                  |
| ------------ | --------------------- | ----------------------------------------------------- |
| 模型请求数   | 16 次/任务            | 重试也计数，请求前检查                                |
| 工具调用数   | 32 次/任务            | 失败及恢复后的重新执行也计数                          |
| 用量预算     | 400,000 预算单位/任务 | 请求前预留，有供应商总 token 用量时结算               |
| 执行时间预算 | 300 秒/任务           | 统计模型与工具等待、重试等待；等待用户作答不计入      |
| 单次模型等待 | 90 秒                 | 临时故障最多自动重试一次                              |
| 单次工具等待 | 60 秒                 | 错误返回模型，由模型决定后续动作                      |
| 重试等待     | 500 毫秒              | 仅超时、网络、限流、服务不可用自动重试                |
| 连续无进展   | 3 次                  | 同一只读工具、规范化参数和结果重复时停止，忽略调用 ID |
| 每次继续     | 6 轮决策              | 到达片段上限后保存进度并暂停                          |
| 完成步骤修正 | 2 次/任务             | 超限停止，不采纳未通过验收的结束语                    |

未知 token 用量保留预留值，不按零计算。预留使用 UTF-8 字节数、协议余量与输出上限估算，不是模型 tokenizer 的精确结果，也不是费用上限。程序崩溃后无法确认结果的请求保留用量与时间预留，避免恢复后把未知消耗清零。执行时间不是任务从创建到结束的总墙钟时间，也不覆盖所有同步处理耗时。

等待过程中约每 100 毫秒检查暂停标记；它能结束本地异步等待，不能撤销供应商已接受的请求，也不能强制结束已经启动的阻塞原生操作或 Python 子进程。因此这里的超时是 Agent 等待上限，不是底层进程资源隔离。操作结果与检查点仍以事务提交为准。

## 上下文组装 ContextBuilder

每次模型调用重新构建请求视图，原始消息与完整证据继续保存在检查点中。

- 固定保留系统规则、复习目标、教材版本与章节、完成条件、到期知识点、已保存题目及实际提交状态。
- 原文使用编号、页码、章节、100 字预览与长度建立索引。`read_source` 可通过 `start_char`、`max_chars` 按 Unicode 字符分页读取，单次最多 2,000 字，并返回下一段位置。
- 最近历史最多保留 8 组；一次工具调用消息与对应的全部结果不可拆开。只保留连续的最近历史，不跳过较大的新结果后把旧结果伪装成最新结果。
- 输入默认不超过 24,000 估算单位，包含工具定义。估算按 UTF-8 字节数加协议余量进行；与精确 token 数不同。
- 孤立或不完整的工具消息被拒绝；固定状态或最新必要工具批次仍超预算时停止，避免默默丢掉必要结果。
- 模型隐藏推理不进入下一轮请求或结构化追踪导出。

这里采用确定性的状态摘要与历史裁剪，没有调用额外模型生成摘要，也没有自动证明裁剪后的回答质量。执行记录保留输入估算、完整历史估算、保留及省略消息数，便于后续对照评测。

## 完成验收 CompletionValidator

模型返回结束文本后，由程序读取 SQLite 快照，核对任务条件、题目与选项结构、来源编号及章节、实际提交与保存状态、唯一记分事件、到期知识点覆盖以及待执行工具。

| 结果              | APP 行为                                             |
| ----------------- | ---------------------------------------------------- |
| `awaiting_answer` | 已保存一道待答题，等待用户提交                       |
| `needs_repair`    | 题数不足、漏记结果或遗漏到期目标，发送具体待办后继续 |
| `completed`       | 完成条件与实际入库状态通过，接受结束文本             |
| `rejected`        | 结构或持久化状态不一致，停止任务                     |

“必须引用教材”核验来源存在与范围有效，不证明原文能推出题目答案。参考答案仍由模型生成；验收中的 `content_quality` 始终为 `not_assessed`。模型正确率、引文支持程度及教学质量继续使用独立质量评测和人工复核。

## 恢复与兼容

不新增数据库表；控制状态、上下文报告、完成条件与报告随 `review_runs.record` 保存。记分与检查点仍在同一事务中提交，重复用户提交或工具投递不会重复累计练习次数。

旧记录缺失新字段时采用默认值，旧提示词 v1/v2 可读取和继续；旧任务没有记录的 Harness 用量与时间不会被追溯重建。已完成旧任务可继续查看，不会自动补跑验收。新任务开始后固定自己的完成条件与策略。
