# 知识卡导入与人工审核流程

## 目标

在正式发布前，将 100–300 条经过人工复核、带真实来源的知识卡安全导入本地内容库。开发阶段的演示数据不得改标为“已核验”。

## 支持格式

- JSON：顶层为知识卡数组，或包含 cards 数组的对象。
- CSV：UTF-8 编码，第一行为字段名；多标签、多个来源使用竖线分隔。
- 单个文件最大 5 MB。

模板位于 examples/cards-import-template.json 和 examples/cards-import-template.csv。

## 必填字段

| 字段                                          | 要求                                |
| --------------------------------------------- | ----------------------------------- |
| id                                            | 本地唯一；CSV 留空时应用生成 UUID   |
| schemaVersion / schema_version                | 当前必须为 1                        |
| language                                      | 当前必须为 zh-CN                    |
| topicId / topic_id                            | 稳定的领域标识                      |
| topicLabel / topic_label                      | 简体中文领域名                      |
| tags                                          | JSON 数组；CSV 用竖线分隔           |
| question                                      | 12–45 个字符，聚焦一个现象          |
| shortAnswer / short_answer                    | 40–120 个字符，先直接回答           |
| explanation                                   | 180–500 个字符                      |
| difficulty                                    | beginner、general 或 advanced       |
| estimatedReadSeconds / estimated_read_seconds | 30–90 秒                            |
| trustStatus / trust_status                    | 见下方可信状态                      |
| sourceRefs 或 CSV 来源字段                    | “已核验”内容至少一个 HTTPS 真实来源 |
| createdAt / created_at                        | ISO 8601；CSV 留空时使用导入时间    |

contentFingerprint 会在导入时根据问题和简短答案重新计算，不能用伪造指纹绕过去重。

## 可信状态

- verified：人工复核过，且保存了实际访问的 HTTPS 来源。
- source_grounded：只有应用实际取得并保存过来源片段时才可使用。当前导入流程不会自动证明该状态，需审核负责人确认。
- ai_unverified：AI 生成且未完成独立来源核验。
- demo_unreviewed：开发/演示内容，未经项目人工审核。

模型输出进入应用时会被 Rust 核心强制改为 ai_unverified，并丢弃模型自行输出的来源链接。

## 100–300 条正式内容流程

1. 内容编辑按模板编写初稿，避开医疗诊断、法律意见、投资建议、实时政治和依赖实时数据的问题。
2. 事实核验人员实际打开来源，确认来源可访问、能支持核心结论，并记录标题、发布者、URL 和访问日期。
3. 第二位审核人员检查问题是否单一明确、答案是否直接、解释是否无夸张或唯一化争议结论。
4. 审核负责人将通过的卡片标记为 verified；未完成复核的内容保留 demo_unreviewed 或 ai_unverified。
5. 每批建议 30–50 条，先在测试数据库导入，检查拒绝、精确重复和近似重复。
6. 随机抽检至少 20%，覆盖所有 8 个领域；发现系统性问题时退回整批。
7. 使用正式发布构建导入完整内容包，人工浏览每个领域至少 5 张并检查最小窗口滚动。
8. 内容包随签名应用版本发布，不用未签名远程文件替换。

人工导入卡不受 AI 动态缓存的 30 张上限影响；只有模型生成且标记为缓存管理的卡片会按创建时间保留最近 30 张。“清除全部本地数据”仍会删除所有非内置导入和生成内容。

## 导入失败处理

- 字段格式错误、高风险内容或不安全来源：拒绝，不入库。
- 指纹或问题相似度重复：跳过并计入重复数。
- “已核验”但没有来源：拒绝。
- 模型批量生成中任一结构解析失败：整批丢弃。
- 数据库异常：保留现有内容和系统凭据，主界面回退到随包演示卡。
