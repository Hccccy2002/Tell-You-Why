## 文件说明

- `documents/`：35 篇适合人工阅读的 Markdown，附作者、许可、原文链接和适用范围。
- `corpus.jsonl`：RAG 入口，UTF-8，每行包含正文 `text` 和来源字段；尚未切成检索块。
- `manifest.json`：35 篇资料的元数据清单，不重复存放正文。
- `excerpts/`：选中范围的原始文本节选，只统一换行，不进行正文清洗。
- `raw/`：固定 Git 提交下的原始文件字节快照、README、完整许可证和辅助参考资料。
- `line-maps/`：`corpus.jsonl` 中正文的行号到原始源文件行号的映射，均为从 1 开始的行号。
- `provenance/`：仓库和 Git 树记录、下载哈希、生成统计、完整性检查结果。
- `selection.json`：人工选择的文件、章节、主题、难度和具体使用限制。
- `fetch_sources.py`：按固定 Git 提交下载，并使用 Git blob SHA-1 与目录记录核对。
- `build_corpus.py`：离线重建正文、目录、元数据和行号映射。
- `validate_corpus.py`：核对正文、节选、源文件、许可、范围和行号映射的完整性。

## 使用边界与质量记录

已检查作者与仓库来源、原始许可、下载文件哈希、章节边界和提取结果；**没有将全文逐条人工核验为事实正确**。统一使用 `source_and_extraction_checked_not_fact_verified` 标记。

原文的图、图像化表格和 R 排版代码没有执行或 OCR。文字正文中的 Markdown 表格和公式保留；无法纯文本提取的部分保留明确占位，记录在 `omitted_nontext_blocks` 中。不能根据未收录图片推断电路结构、时序或数值。涉及这些问题时应查看原始来源。25 篇资料含至少一个此类非文本占位。

原书中关于具体制程、CPU/GPU 型号、DDR/PCIe 代际、价格、速度和“目前”的表述有时间范围，相关资料已附 `limitations`。程序必须把这些限制随检索结果传递给模型，不能把旧案例当作当前事实。没有编造来源的发布日期：无法确认时 `source_published_at` 为 null；采集日期与 Git 快照日期不等于出版日期。

抽查发现《Hello 算法》“内存与缓存”原文件中的“数据结构的内存效率”小节含“同一块内存不能被多个程序共享”的过宽概括；该小节没有被选入 `corpus.jsonl`。原文件完整快照仍保留在 `raw/`，以便追溯。此例也说明开源和有出处不等于逐条事实已核验。

部分资料讨论相近概念是有意保留的，例如存储器、缓存和局部性。它们便于比较解释和来源，但同一本教材的章节不能当成多个独立来源进行“交叉验证”。尚未完成语义去重。

## 后续接入 RAG

1. 只读取 `corpus.jsonl` 的 `text` 作为可检索正文；不要递归索引整个目录，否则会把原始整章、元数据、许可和重复内容一起索引。
2. 切块时保留 `id`、`section_path`、`source_url`、`commit`、`license`、`limitations` 以及块在正文中的起止位置。
3. 引用原文时使用 `line-maps/` 还原源文件位置，并从 `raw/` 或 `excerpts/` 取证据；清洗后的文本不是完整原文的字节副本。
4. 标有图表占位的文本不能支持图表细节问题；来源条件不足时返回“资料不足”。
5. 同一源文档的邻近章节若用于评测，应按原始文件或书籍分组划分开发/测试任务，避免切片泄漏导致过高的检索效果估计。

这些文件是原始资料库，**不符合现有知识卡 JSON/CSV 导入格式**。本次没有修改应用、写入 SQLite、请求模型、生成向量或生成知识卡。

## 重建

需要 Python 3.10 或更高版本，仅使用标准库。在本目录运行：

~~~text
python fetch_sources.py
python build_corpus.py
python validate_corpus.py
~~~

原始文件已在本地时，后两步完全离线。下载脚本固定到已记录的提交，不会自动追踪上游 main。全文快照、提取结果与完整性报告均保留，可重新审阅来源和提取过程。
